# {{AGENT_NAME}} Agent Vault — Schema & Wiki Conventions

This file tells the AI agent how the vault is structured, what conventions to follow,
and what flow to execute for each operation. Load at the start of every session.

---

## Architecture

Three layers with strict roles:

1. **`raw/`** — Immutable sources. The agent reads but NEVER modifies.
2. **`wiki/`** — Markdown generated and maintained by the agent. The user reads; the agent writes.
3. **`CLAUDE.md`** (this file) — Schema that defines structure, conventions, and flows.

Personal vault (user's daily notes, weekly reviews): separate repo and directory.

## Directory Structure

```
agent-vault/
├── raw/
│   ├── articles/              ← web clips (Obsidian Web Clipper, etc.)
│   ├── transcripts/           ← meetings, podcasts, voice notes
│   ├── notes/                 ← manual notes from Telegram or Claude Code
│   └── personal_vault_sync/   ← files synced by obsidian_sync connector
├── wiki/
│   └── {topics}/              ← generated by vault-ingest.py
├── outputs/                   ← generated artifacts (analyses, tables)
├── index/
│   ├── MASTER_INDEX.md        ← content catalog
│   ├── INGEST_QUEUE.md        ← manual ingestion queue
│   ├── RECENT_UPDATES.md      ← last ingestion cycle summary
│   ├── log.md                 ← chronological append-only log
│   ├── status-operativo.md    ← twice-weekly system status
│   ├── perfil-identidad.md    ← user identity profile (updated Sundays)
│   └── supervisor-reports/    ← daily vault-health.py reports
└── _templates/
    ├── article.md
    └── concept.md
```

## Frontmatter Standard

All files in `wiki/` and `outputs/` must have this minimum frontmatter:

```yaml
---
title: "Descriptive title"
type: article | concept | startup-update | market-data | output | query-answer
topic: your-topic-folder
status: raw | in-progress | reviewed | archived
date: YYYY-MM-DD
source: "URL or 'manual' or 'agent'"
tags: []
---
```

## Operation: INGEST

### Detecting pending files

Files in `raw/` are immutable. The `log.md` tracks what was processed.
To find pending files:

1. List all `.md` files in `raw/` subdirectories
2. Search `log.md` for lines `## [*] ingest | filename` — each one names a processed file
3. Files NOT mentioned in the log are pending

### Ingest flow (per file)

1. Read the file from `raw/`
2. Generate a wiki page summary using the LLM
3. Write the page to `wiki/{topic}/` using the appropriate template
4. Update `MASTER_INDEX.md` — add the entry under the correct topic
5. Append to `index/log.md`: `## [YYYY-MM-DD] ingest | filename`
6. Update `RECENT_UPDATES.md` with cycle summary

---

## Operation: QUERY

When the user asks a question about vault content:

1. Read `MASTER_INDEX.md` to identify relevant pages
2. Read those pages and synthesize the answer with citations
3. If the answer is valuable (analysis, non-trivial synthesis): archive it in `wiki/`
   - Use `type: query-answer` in frontmatter
   - Add entry to `log.md`: `## [YYYY-MM-DD] query | question summary`

---

## Log Format

`index/log.md` is append-only. Parseable prefixes:
- `## [YYYY-MM-DD] ingest | filename`
- `## [YYYY-MM-DD] query | question summary`
- `## [YYYY-MM-DD] lint | N issues found`

**NEVER overwrite. Only append.**

---

## Agent Rules

1. `raw/` is immutable — read, never write.
2. `index/log.md` is append-only — never overwrite existing lines.
3. Always read `MASTER_INDEX.md` before answering a query.
4. Each ingest updates: wiki page + related pages + index + log.
5. Valuable query answers go back into the wiki as `query-answer`.
6. All new files must have frontmatter.
